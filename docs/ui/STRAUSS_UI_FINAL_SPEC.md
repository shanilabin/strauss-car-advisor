# Strauss Car Advisor — Final UI Specification

**סטטוס:** מאושר לעיצוב ולמימוש, בכפוף לאימות חוזי API; סוגיית אימות העיסוק וקבוצת הזכאות פתוחה.  
**תאריך:** 14.10.2026  
**מסמכי ייחוס:** `UX.md`, `ARCHITECTURE.md`, `UI_LAYOUT_SPEC.md`, `UI_DESIGN_SPEC.md`.  
**תחולה:** `/`, `/c/[id]`, `/form`, `/rep` — מחשב, נייד, Light/Dark.  
**כלל בסיס:** ה־UI מציג יכולות ונתונים שקיימים ב־Backend בלבד; אין ליצור תהליכים עסקיים, נתונים פיננסיים, סיווג זכאות או תוצאות חדשות בצד הלקוח.

## 1. מעמד החלטות והיררכיה

- **מאושר:** החלטות הפריסה, השפה החזותית, הרכיבים וההתנהגות המפורטות במסמך זה; המסמך משקף את אישור המשתמשת לכל ההחלטות שהוצעו.
- **מחייב אימות טכני:** צורת ה־payload, שיוך אירועי סוכן להודעות, זמינות גרף מפל ותוצאות חלקיות, וביצוע המעברים בפועל לפי חוזה ה־API. אלו אינן החלטות UI חדשות.
- **פתוח להכרעת הצוות:** מקור אמין לעיסוק ולקבוצת הזכאות, וכתוצאה מכך הרשאות עריכת העיסוק והצגת מצב האימות. אין לסמן פרופיל כמאומת כשלא אומת.
- במקרה של סתירה: לוגיקת התחום וחוזה API מאומת קובעים אילו נתונים ופעולות קיימים; מסמך זה קובע את הצגתם. אין לשנות או להשלים לוגיקה עסקית ממסקנת UX.

## 2. שפה חזותית ו־Design System

### 2.1 זהות

**Premium Editorial Tech / Precision Tech**: מוצר טכנולוגי חדשני וייחודי אך מקצועי, עם היררכיה נועזת בתוצאות וצפיפות מבוקרת במסכים תפעוליים. ללא אסתטיקת AI גנרית.

**איסורים מחייבים:** `border-radius: 0`, ללא `box-shadow`, Glow, Neon, gradients, Glassmorphism, אנימציות קופצניות או ריצוד בלתי פוסק. תחושת עומק נוצרת באמצעות קומפוזיציה, קווים, גודל, ריווח וניגודי צבעים.

### 2.2 צבע וטוקנים

| Token | ערך בסיס | שימוש |
|---|---|---|
| `brand.cobalt` | `#2247DD` | Primary CTA, בחירה, Focus |
| `brand.lime` | `#D4F45B` | הדגשות נקודתיות בלבד |
| `brand.navy` | `#142352` | סרגל עליון, טקסט/משטחים כהים |
| `surface.light` | `#F5F6FA` | רקע Light |
| `surface.dark` | `#111A33` | רקע Dark |

- מגדירים `background`, `surface`, `surface-raised`, `text`, `text-muted`, `border`, `primary`, `primary-on`, `accent`, `focus`, וכן טוקנים סמנטיים `success`, `error`, `warning`, `info` בנפרד לשני המצבים. אין להניח שצבע מותג הוא בהכרח צבע הצלחה פיננסית.
- כל צבע מותאם לניגודיות WCAG AA; ערכי HEX לטוקנים סמנטיים משניים הם החלטות מימוש הכפופות לבדיקות ניגודיות, לא הרחבה של הפלטה המאושרת.
- מצב בהיר וכהה, מתג בסרגל העליון; בחירה נשמרת לאורך רענון; לפני בחירה משתמשים ב־`prefers-color-scheme`.
- סרגל עליון Deep Navy גם ב־Light Mode; ב־Dark Mode צבע כהה יחסית לרקע.

### 2.3 טיפוגרפיה וריווח

- **Secular One** לכותרות מרכזיות וגדולות (דף פתיחה, כותרות בולטות); **Heebo** לטקסט, צ'אט, טפסים, טבלאות וכותרות משניות.
- סכומים גדולים: Heebo Black + `font-variant-numeric: tabular-nums`; מידע תפעולי: Heebo Regular/Medium/SemiBold.
- ריווח בסיס 4px; סולם `4 / 8 / 12 / 16 / 24 / 32 / 48px`. ריווח נדיב באזורי Hero ותוצאה, קומפקטי ברשימות, בצ'אט ובמסך נציג.
- סט טכני התחלתי לכרטיס תוצאה: padding 32px במחשב, 20px בנייד; הפרש 56px / 44px; סכומי נטו משניים 24px / 20px; הסבר 16px. לבצע בדיקת התאמה למסכים אמיתיים.

### 2.4 כללי רכיבים

- Primary CTA: משטח Cobalt מלא; Secondary: טקסט עם אייקון או מסגרת דקה.
- כרטיסים רגילים: משטח ניטרלי, גבול `1px`; כרטיס התוצאה: משטח מודגש, ללא צל או עיגול פינות.
- שדה צ'אט: מסגרת מלאה; שדות בפרופיל ובטופס: קו תחתון ברור; Focus ב־Cobalt.
- תגיות זכאות/אי־זכאות/המתנה/אישור: רקעים סמנטיים עדינים, טקסט מפורש ואייקון; לעולם לא צבע לבדו.
- Lucide לפעולות ומצבים; אייקוני סוגי הנעה גאומטריים, שטוחים, חד־צבעיים, ללא דקורציה.
- Hover שינוי עדין במשטח או גבול; Focus נראה; Active רקע/פס/סימון; Disabled ניגודיות מופחתת עם קריאות תקינה.

## 3. מבנה מסכי העובד

### 3.1 Shell קבוע

- **Topbar קבוע:** שם המוצר מימין, חיווי מצב קצר במרכז, פעולות פרופיל ומעבר Light/Dark משמאל. **אין** כפתור נפרד של פעולות AI בסרגל.
- **Adaptive Layout** ללא החלפת מסלול עמוד עבור כל שלב; השיחה והתוצאות משנות רוחב ודומיננטיות לפי ה־state.
- **Collecting:** צ'אט גדול, פרופיל זמין בהקשר איסוף; לא להציג אזור תוצאות ריק דומיננטי.
- **Options:** גלריית כרטיסים מובילים גדולה במרכז, יתר החלופות ברשימה קומפקטית מתחת; לא זכאים בתחתית עם סיבה וללא מספר נטו.
- **Comparison/Presented:** מימין רשימת רכבים, במרכז השוואה רחבה, משמאל צ'אט צר פתוח וקבוע.
- **Waiting Rep:** משמרים את תצוגת החלופות/השוואה עם באנר ברור ותוצאה חלקית ככל שקיימת; לא נועלים את התצוגה.
- **Correction/Change:** בחירת חלופה אחרת או שינוי פרופיל מעדכנים נתונים ותוצאה בלי ניווט החוצה.

### 3.2 מידות, גלילה ועריכה

- רשימת רכבים מימין: `200px` ברירת מחדל, מתרחבת ל־`280px` לפי דרישה.
- צ'אט צר משמאל: יעד מימוש `280px`, מתרחב זמנית על חשבון אזור ההשוואה; בזמן איסוף הנתונים הוא רחב כברירת מחדל.
- אזור ההשוואה מקבל את יתרת הרוחב וגולל את העמוד; פאנלי הצד נשארים גלויים, ורשימת רכבים ארוכה יכולה לגלול פנימית; להימנע משלושה פסי גלילה מתחרים ככל האפשר.
- פרופיל נפתח ב־**Side Drawer מימין**, מעל התוכן, אינו תופס עמודה קבועה בהשוואה; יעד רוחב 400px במחשב ורוחב זמין בנייד.
- Topbar: גובה יעד `64px` במחשב, `56px` בנייד. Breakpoint ראשי יעד `1024px`. כל ערכי היעד נבדקים מול התוצאה החזותית בפועל.

### 3.3 דף פתיחה `/`

- פריסה א־סימטרית: מימין כותרת Secular One גדולה, תיאור קצר, כפתורים קיימים **"בואו נתחיל"** ו־**"נסו עם עובד לדוגמה"**.
- משמאל קומפוזיציית נתוני הדגמה קיימים: כרטיסי רכב ונטו בלבד, ללא מידע מומצא או פעולה נוספת.
- רכיבים נכנסים בהדרגה באנימציה קצרה; בנייד הכותרת והכפתורים לפני הקומפוזיציה.

### 3.4 צ'אט `/c/[id]`

- הודעות בוט ללא בועות; הודעות משתמש מובחנות באמצעות תווית, יישור, קו וריווח — **ללא רקע בועה נפרד**.
- תשובות מהירות כפקדים מלבניים; קלט טקסט חופשי ושדה הקלדה בגבול מלא קבועים בתחתית.
- תוצאות מספריות מה־Backend מוצגות בכרטיסי נתונים בלבד, **לא בטקסט חופשי של LLM**.
- **"הצג פעולות AI"** מופיע מתחת להודעת בוט רלוונטית ופותח Timeline של `tool_call`, `tool_result`, `guard`, `model` לפי אירועים שסופקו; ברירת מחדל סגור. בצ'אט צר ניתן להרחיב זמנית לפני פירוט.
- מידע סודי ופרטים מזהים לא מוצגים בתצוגה הטכנית; אין להציג JSON רגיש. שיוך `turn_id` להודעות טעון אימות API.

### 3.5 גלריית אפשרויות וכרטיסי רכב

- בגלריה הראשונית: החלופות המשתלמות הגדולות בראש, יתר החלופות ברשימה, לא־זכאיות בתחתית. דירוג לפי תוצאות מנוע בלבד.
- במצב השוואה: כל כרטיס 200px בתצוגה צרה, בשתי שורות — שם הרכב, אייקון הנעה, הפרש נטו וסימון זכאות.
- בהרחבה ל־280px: מידע הנעה, קבוצת רכב אם זמין, זכאות והסבר קצר; אין להוסיף תמונות רכב שלא קיימות בדאטה.
- בחירה: רקע בהיר, פס אנכי בצבע Cobalt וסימון נבחר; התוכן באזור המרכז מתעדכן ללא מעבר מסך.
- לא זכאי: כרטיס מעומעם, **ללא סכום נטו**, עם הסבר הזכאות; ממתין לנציג: סטטוס מתאים וסייג לתוצאה.

### 3.6 כרטיס השוואה מרכזי

סדר ההיררכיה המאושר:

1. שם החלופה והזכאות כאשר זמינים.
2. **הפרש הנטו החודשי** הוא המספר הגדול והדומיננטי ביותר, עם סימן ומילים (יותר/פחות).
3. בתוך **אותו כרטיס** שני סכומי משנה: נטו היום ונטו בחלופה.
4. הסבר קצר בן שתי שורות מהמנוע.
5. גרף מפל קומפקטי כברירת מחדל; הרחבה לגרף מפורט מתוך פלט `waterfall` של המנוע.
6. "פירוט מלא" מתקפל: נתוני מס, ביטוח לאומי, בריאות, פנסיה, קרן השתלמות, שווי שימוש, השתתפות, עלות חברה ותקציב, החזרים/אחזקה ככל שקיימים בחוזה.
7. "למה?" ליד סכומים כשיש מקור; שורת שקיפות עם גרסאות/שנות מס שנשלחו מהשרת. אין להרכיב מקורות או ערכי מס בצד לקוח.

- בתצוגת מפל קומפקטית יש מעט צבע ותוויות; במורחבת עמודות חדות וברורות וקריאות גבוהה. אין להמיר פירוק של המנוע לגרף סכמטי במוצר האמיתי.
- אין להציג סכום לא ידוע או לא מאומת כוודאי.

### 3.7 המתנה לנציג ותוצאה חלקית

- באנר בראש ההשוואה: מה חסר ומה ממתין לתשובת הנציג; לא Warning אדום.
- כרטיס התוצאה שומר על אותה פריסה: תוצאה תקפה חלקית מסומנת "משוערת" והנתון התלוי בתשובת הנציג מסומן; אם אין סכום תקף, מציגים "ממתין לנתונים", לא הערכה מחושבת בדפדפן.
- מעבר בין חלופות נשאר זמין. תזוזה קצרה של כרטיסי רכב יכולה לסמן מעבר/שינוי **בלבד**, בלי להציג תהליך חישוב מתמשך שלא מתקיים. אין Glow או shimmer מתמשך.
- לאחר תשובת נציג: הודעת מערכת בצ'אט, שינוי הסטטוס, חישוב מחדש בשרת והדגשה רגעית של המספרים שהשתנו.

## 4. נייד

- פריסה מדורגת במקום שלוש עמודות: Collecting = צ'אט מסך מלא; Options = גלריית חלופות; Comparison = תוצאה/גרף ברוחב מלא.
- הצ'אט זמין תמיד דרך פעולה קבועה ונפתח מעל התוכן; הפרופיל נפתח במגירה, וטיפול בשדות עובד גם ב־375px.
- כרטיס התוצאה נשאר אוורירי ומודגש, יתר הרשימות והטפסים קומפקטיים; שטחי מגע לפחות 44px.
- אין ליצור לשוניות או פעולות עסקיות נוספות ללא בסיס בחוזה הקיים.

## 5. מסך הנציג `/rep`

- **Precision Tech אחיד:** רקע ניטרלי, קווים דקים, ללא משטח צד כהה דומיננטי; רשימת שאלות מימין, פאנל טיפול משמאל.
- רשימת השאלות מציגה תור, שאלה, זמן, סטטוס ומינימום הקשר; הנבחרת מסומנת בפס Cobalt.
- פאנל הטיפול מציג שאלה מלאה, פרטי עיסוק/קבוצה/רכב נוכחי/מבוקש בהתאם לנתונים המותרים, שדה תשובה, תאריך תוקף אופציונלי **רק אם נתמך ב־API**, ושליחה.
- מניעת שליחה כפולה באמצעות Disabled/Loading; שאלות חדשות ועדכונים בזמן אמת לפי התשתית המתוכננת.
- **לא מציגים** שכר, הפרשות או תמליל שיחת העובד לנציג.

## 6. מצב טופס `/form`, שגיאות ונגישות

- מצב טופס גיבוי משתמש באותם מודלי פרופיל/תוצאה, ללא שכבת שיחת AI וללא מנוע חישוב נפרד.
- עיבוד: חיווי מקומי בצ'אט עם שם פעולה **אם ידוע בפועל**; שגיאת רשת: הודעה סמוכה ושמירת טקסט; AI לא זמין: מעבר לטופס בהתאם לתגובה אמיתית.
- בקרה על מצבי ריק, טעינה, שגיאת רשת, לא־זכאי, רכב חסר, חסר מידע, המתנה לנציג, תוצאה מאושרת ותוצאה משוערת.
- RTL מלא עם `<bdi>` לשמות לועזיים, `Intl.NumberFormat('he-IL')`, `tabular-nums`, ניגודיות WCAG AA, מיקוד מקלדת, `aria-live` מתון ו־`prefers-reduced-motion`.

## 7. Motion

| פעולה | התנהגות יעד |
|---|---|
| כניסה לדף הבית | הופעה מדורגת וקצרה |
| מעבר בין פריסות | 250–350ms, easing מאופק |
| בחירת רכב | שינוי סימון ותוכן תוצאה ללא קפיצה |
| שינוי מספר | 300–500ms לכל היותר; אין אנימציה שממציאה תוצאות ביניים |
| הרחבת גרף/צ'אט/פרופיל | מעבר קצר, ללא Spring קופצני |
| המתנה לנציג | חיווי סטטוס; ללא תנועה אינסופית שמדמה חישוב |
| תשובת נציג | הדגשה קצרה של שדות שהתעדכנו |

## 8. מה אינו חלק מהמוצר

- מסך `/demo` ייעודי **בוטל מה־MVP**: אפשר להדגים עם שני חלונות/טאבים עצמאיים של עובד ונציג.
- אין פאנל Under the Hood נפרד בסרגל; אירועי AI נמצאים בצ'אט.
- אין תמונות רכב, פילטרים, פעולות חיזוי, מחשבונים בצד לקוח או פונקציונליות חדשה שלא קיימת במפרט וב־API.
- אין לשנות נוסחאות, קבוצות רכב, כללי זכאות, נתוני מס או אחוזי השתתפות כחלק מתכנון ה־UI.

## 9. נושא פתוח יחיד להכרעה עסקית — אימות קבוצת זכאות

**מצב:** נשלחה שאלה לצוות וממתינים להחלטה.

- קיים במבנה התחום שיוך עיסוק → קבוצה, אך בחירת עיסוק עצמית אינה אימות הרשאה ארגונית.
- מוסכם שהעובד **לא בוחר את קבוצת הרכב ישירות**; ההצגה נגזרת מהעיסוק/נתון הארגון כפי שהשרת קובע.
- **טרם הוכרע:** מהו מקור האמת לעיסוק ולקבוצה, האם העיסוק ניתן לעריכה למשתמש לא מאומת, והאם דמו של עובד פיקטיבי נחשב מאומת או רק הדמיה.
- **עד להחלטה:** לא להציג אייקון נעילה/כיתוב "מאומת" או הבטחת הרשאה ארגונית ללא בסיס; לא לקבע UI של עריכת העיסוק. את יתר הפרופיל ניתן לממש כמתוכנן.
- לאחר תשובת הצוות יש לעדכן רק את התנהגות שדות העיסוק והקבוצה, מיקרו־קופי ואולי מקור הנתונים; יתר מפרט ה־UI סגור.

## 10. בדיקות מסירה למפתחת — Definition of Done

- [ ] Desktop Collecting, Options, Comparison, Waiting Rep מציגים את ההיררכיה הנכונה.
- [ ] Header קבוע; פרופיל נפתח מימין; Chat פתוח משמאל בהשוואה; רשימת רכבים 200/280px מימין.
- [ ] גלריה ראשונית בנויה מכרטיסים מובילים ורשימה קומפקטית; לא זכאים בתחתית בלי הפרש נטו.
- [ ] כרטיס תוצאה אחד: הפרש נטו דומיננטי ושני סכומי נטו משניים, הסבר, גרף ופירוט מתקפל.
- [ ] המתנה לנציג אינה מציגה מספר לא מאומת כוודאי; תשובה מעדכנת UI מתוך תוצאת Backend.
- [ ] צ'אט ללא בועות; פעולות AI מתקפלות בתוך ההודעה הרלוונטית רק אם API תומך בשיוך.
- [ ] `/rep` אינו מציג מידע פיננסי רגיש; שליחה כפולה נמנעת.
- [ ] `/form` משתמש באותן תוצאות חישוב ולא מכיל מנוע חדש.
- [ ] Light/Dark עובדים; הבחירה נשמרת; Secular One + Heebo נטענים; ללא radius/shadow/glow/gradient.
- [ ] בדיקות 375px, 1024px, Desktop ומקרן; RTL/LTR; מקלדת; 44px; Reduced Motion; WCAG AA.
- [ ] אין מסך `/demo` נפרד או יכולת חדשה שלא קיימת בשרת.
- [ ] סוגיית אימות קבוצת הזכאות נשארת מסומנת OPEN, ולא משוחררת כהחלטה סגורה.
